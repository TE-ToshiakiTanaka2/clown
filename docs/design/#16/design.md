# Design: #16 Enemy AI variety and pixel-art quality overhaul

## Context

The Godot 4.7 game has four stages and one deterministic player-contact
classifier. Every current enemy is either a Goomba that walks and reverses or a
Turtle with WALK/SHELL/SLIDING states. The same two scenes are repeated across
all stages. Runtime art is generated by `game/tools/gen_sprites.py`, but the
current actors are mostly 16×16, use two walk frames, flat fills, and very small
palettes. Collision sizes and the four-stage progression must remain stable.

Issue #16 adds three orthogonal AI families—flying swoop, armored charge, and
ranged fire—while retaining the two existing families as the readable baseline.
It also replaces all major actor art and enriches items/tiles through the same
deterministic generator. The generated concept sheet
[`art-direction.png`](art-direction.png) is an art-direction reference only; it
is not shipped at runtime and is not mechanically downscaled into game sprites.

## Architecture Overview (delta)

All enemies remain independent packed scenes and join the `enemies` group. Each
enemy that can physically contact the player owns exactly one `ContactArea` and
asks `Player.classify_enemy_contact()` for the geometric outcome. The enemy then
maps that outcome to its own policy: Goomba/Bat are defeated by a stomp, Turtle
changes state, Spiny treats a stomp as damaging contact, and Cannon is destroyed
by a stomp. Compatible enemies continue exposing `defeat_by_shell()`.

The player joins a `player` group once in `_ready()`. New AI resolves and caches
that one target once instead of scanning the scene tree per frame. State machines
use bounded timers and exported tuning. Cannon tracks live projectiles and never
exceeds `max_active_projectiles`; each projectile expires by distance, lifetime,
world impact, or player impact.

Production art stays code-reviewed and reproducible. The generator expands the
shared palette and actor grids: SMALL actors use 24×24, SUPER player uses 24×32,
and existing 16×16 tile/item contracts remain where scene geometry depends on
them. PNGs use RGBA8, hard pixel clusters, consistent navy outlines, three-tone
shading, selective highlights, and nearest-neighbor rendering.

## Interface Design (delta)

### Public API / Functions

| Name | Signature | Description |
| --- | --- | --- |
| `SwoopBat.defeat_by_shell` | `() -> void` | Stops AI, awards score, and removes the Bat. |
| `Spiny.defeat_by_shell` | `() -> void` | The safe way to defeat Spiny; stops all state timers. |
| `Cannon.defeat_by_shell` | `() -> void` | Disables firing/contact and removes the Cannon. |
| `EnemyProjectile.initialize` | `(direction: Vector2) -> void` | Normalizes and stores the immutable shot direction. |
| `EnemyProjectile.expired` | signal `(projectile: EnemyProjectile)` | Lets Cannon release its active-shot slot. |
| `Cannon.active_projectile_count` | `() -> int` | Observable bounded-spawn count for tests. |

### Type Definitions (delta)

- `SwoopBat.State { PATROL, DIVE, RETURN, DEFEATED }`.
- `Spiny.State { PATROL, WINDUP, CHARGE, STUNNED, DEFEATED }`.
- `Cannon.State { IDLE, WARNING, COOLDOWN, DEFEATED }`.
- Sprite contract:
  - player/goomba/turtle/bat/spiny/cannon: 24px-wide actor frames;
  - SUPER player: 24×32;
  - tile atlas cell and pickup/coin frames: 16×16;
  - flag: 16×48;
  - transparent pixels outside every actor silhouette.

## Data Flow

### Targeted AI

1. Player enters the `player` group in `_ready()`.
2. Enemy `_ready()` calls `get_first_node_in_group("player")` once and stores a
   weakly validated `Player` reference.
3. Each physics tick reads only cached position/state and applies constant-time
   transitions.
4. If the cached target is freed, the enemy returns to patrol/idle and does not
   reacquire in a tight loop; a deferred one-shot reacquire is allowed.

### Cannon fire

1. IDLE sees a valid target inside horizontal range and vertical tolerance.
2. WARNING plays a visible two-frame glow for `warning_sec`.
3. Cannon verifies the target again and `active < max_active_projectiles`.
4. It instances one projectile, initializes direction, connects `expired`, and
   enters COOLDOWN.
5. Projectile emits `expired` exactly once on every terminal path; Cannon prunes
   invalid references defensively.

## Error Handling

- Every defeat method is idempotent and disables contact/physics before removal.
- AI ignores missing/dead targets and never dereferences an invalid instance.
- Cannon refuses to fire when the scene, muzzle, target, or active slot is absent.
- Projectile direction falls back to a horizontal unit vector when near zero.
- Projectile terminal handling uses one `_expired` guard to prevent double emits.
- Spiny cancels charge/windup on shell defeat and cannot damage after defeat.
- Generator validates rectangular rows and fails on inconsistent sprite grids.

## Art Direction

- **Silhouette first**: Bat wings, Spiny spikes, Turtle shell, and Cannon barrel
  must remain identifiable when viewed at native resolution.
- **Shared outline**: near-navy outline, never pure black, 1px at native size.
- **Value structure**: outline + shadow + base + highlight; highlights occupy less
  area than shadows and face the upper-left.
- **Palette discipline**: shared neutral/skin/metal colors plus one family hue per
  enemy. Avoid single-use near-duplicate colors.
- **Animation**: change weight and silhouette, not only one foot pixel. Walk/fly
  cycles use three frames; attack/warning frames are visually distinct.
- **Originality**: the circus acrobat and creature designs use the generated
  direction sheet as inspiration, not direct Mario franchise sprites.

## Implementation Notes

- Keep current collision shapes while actor frames move to 24px; set existing
  actor sprite scale to `Vector2.ONE` after confirming visual bounds.
- Bat does not collide with world geometry during a dive; its bounded home radius
  prevents escape. Projectile does collide with world and player.
- Spiny top contact calls `take_damage()` then `bounce()` if the player survives,
  making the exception readable without overlapping damage callbacks.
- Generated PNGs and `gen_sprites.py` land in the same commit. Clean regeneration
  must leave `git diff` empty for those paths.
